# E2E-S2.2C — Verification Cache and Resume

## Scope

This block extends the sequential Yahoo verification pilot with persistent
verification evidence and explicit resume. It supersedes the pilot document's
statement that caching and resume are not implemented. It does not cache OHLC
frames, change Portfolio Analysis or enable whole-universe execution.

User-reported live baseline: ten sampled listings across BIT, XETRA, NASDAQ,
NYSE, LSE, AS, PA, SW, CO and ST were VERIFIED and AVAILABLE. That evidence
does not establish coverage of every listing on those venues.

## Cache identity and validity

The SHA-256 filename derives from the complete source listing, mapping contract,
exact UTC request interval, verification version and cache schema version.
Source changes, mapping overrides/version changes, interval changes and verifier
version changes invalidate reuse. Full original evidence remains in JSON.

Reads reconstruct validated contracts and check request/result agreement.
Only checked_at <= now < expires_at is reusable; the configured outcome lifetime
is also enforced on read. Corrupt, mismatched, future-dated or expired entries
are never used as stale successes. Writes use a temporary file and atomic
replacement. A write failure preserves the live result with CACHE_WRITE_FAILED.
Concurrent processes are not coordinated; the intended execution is sequential.

| Outcome | Maximum reuse lifetime |
| --- | --- |
| VERIFIED and AVAILABLE | 24 hours |
| Provider/network errors, including metadata request errors | 5 minutes |
| Other results, including NO_DATA, MISMATCH and incomplete identity | 1 hour |

These caps never extend the underlying verifier's expiry. Error reuse is a
cooldown, not proof that a symbol does not exist. Cached rate-limit diagnostics
still stop the pilot. No automatic retry loop or stale-on-error fallback exists.

## Modes

- prefer-cache: reuse a valid exact match; otherwise verify and persist.
- cache-only: reuse a valid exact match; otherwise return NOT_CHECKED with
  CACHE_MISS, CACHE_EXPIRED or CACHE_INVALID. No provider verification occurs.
- force-refresh: bypass reads and replace the entry with the new outcome.

The default directory is data/cache/scanner/market_data_verifications.
network_verifications counts calls to the verifier, not HTTP requests inside
yfinance. cache_hits and cache_misses are reported separately.

## Resume

Use --resume-report with a report generated by this revised pilot. The command
checks the source-report fingerprint, ordered sample and lookback period. It
retains the original requested_start/requested_end and writes a new run report.
It consults the cache for each item; fresh completed outcomes are reused and
missing/expired outcomes are rechecked in prefer-cache mode. Results from the
report itself are not imported as trusted cache entries.

Keep the same --input-report, --venues, --per-venue, --lookback-days and cache
directory. The two earlier live pilot reports predate the resume signature and
cannot be resumed. Run one new small pilot to populate this cache first.

A fresh run without --resume-report chooses a new exact time window, so it
normally produces cache misses. Resume means finishing/rechecking the original
window; omit resume when intentionally requesting a new window.

Checkpoint writes and cache writes are separate atomic operations. An interrupted
report may omit a just-completed result, but its valid cache entry can still be
reused. Missing or unwritable cache means that verification must be repeated.

## Limits and validation

Existing bounded sample selection and stop-on-rate-limit behavior remain.
The request timeout is not a hard process deadline; underlying metadata calls
may take additional time. Expired verification evidence is not a trading-data
freshness policy. Liquidity/history gates and downstream pricing remain separate.

Offline tests cover round-trip persistence, exact-key invalidation, expiry,
force refresh, corruption, write failure, error cooldown, partial completion,
resume signature validation and CLI cache-only resume with zero verifier calls.
Local subset: 72 unittest tests passed. Full repository regression and live cache
acceptance must run in the user's Windows environment before milestone closure.
